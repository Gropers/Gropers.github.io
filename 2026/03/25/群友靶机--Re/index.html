root

从群友（mooi）wp那得到的完整思路

查看/usr/local/bin/publisher.py文件后发现：如果连接 Redis 失败（ redis.ConnectionError ），脚 本会直接执行 sys.exit(1) 崩溃退出。

猜测它是Systemd 管理的服务，找一下它的配置文件

发现留了一个后门

只要能让该服务停止或崩溃，系统就会自动以 Root 权限向 dev.warning.dsz 的 1234 端口发起反弹 Shell！

局部网络劫持 (ARP & DNS Spoofing)

这个操作的最终目的就是为了让靶机认为 Kali 的 IP 就是 dev.warning.dsz 这个域名的真实归属地

这个操作一共需要kali上开启三个终端

同时在靶机的submini用户终端直接对 Redis 服务下达停止指令（加上 nosave 防止因权限 不足导致的关机失败）：

执行后等待重启就可以发现成功反弹shell

但是要注意因为会再次重启，shell会断开连接，只要再次对 Redis 服务下达停止指令就可以再次获得shell。
